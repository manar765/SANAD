# SANAD | سند
> **المنصة العربية المتكاملة لإدارة التبرعات العينية والمستفيدين والتوزيعات الميدانية**  
> *Arabic-first in-kind donation, beneficiary registry, and field distribution platform.*

---

## 📖 نظرة عامة (Overview)

**سند (SANAD)** هي منصة تشغيلية ومجتمعية متكاملة، مصممة خصيصاً للمؤسسات والجمعيات الخيرية والتنموية لإدارة كافة مراحل العمل الإغاثي والعيني: بدءاً من استلام التبرعات العينية وتوثيقها في المستودعات، وفحص وبحث حالات المستفيدين والتحقق منها وفقاً للمعايير المصرية، وتوليد التوصيات الذكية لترتيب الأولويات، وحتى التنفيذ الفعلي لعمليات التوزيع الميداني ومتابعة التقارير الحية وسجل الرقابة والأمان.

## 🏗️ المبادئ المعمارية والتصميمية (Architectural Principles)

1. **واجهة عربية أصيلة (Arabic-First & Native RTL)**:
   - تصميم واجهات سلس ومتوافق تماماً مع الاتجاه من اليمين إلى اليسار (RTL) باستخدام خط **IBM Plex Sans Arabic** وألوان وتنسيقات SaaS حديثة وراقية.
2. **بنية برمجية نقية وعالية الأداء (Pure Web Stack)**:
   - **الواجهة الأمامية**: Vanilla HTML5, Vanilla CSS3, Vanilla Modern JavaScript دون أطر عمل خارجية ثقيلة، لتحقيق أعلى سرعة تحميل واستجابة.
   - **الخادم**: Node.js & Express في بيئة نمطية (ES Modules).
   - **قاعدة البيانات**: PostgreSQL (Neon Cloud) مع قفل استشاري للمعاملات (`pg_advisory_xact_lock`) يمنع تعارض الهجرة المتزامنة (Deadlock Prevention).
3. **الذكاء الاصطناعي في خدمة القرار البشري (Human-in-the-Loop AI)**:
   - الذكاء الاصطناعي يعمل كأداة مساعدة لاستخراج البيانات من التقارير الاجتماعية غير المهيكلة، مع إشعار استرشادي إلزامي؛ ويبقى القرار النهائي دائماً لموظف الحالة المختص.
4. **الأمان الصارم والامتثال لخصوصية البيانات (Security & PII Protection)**:
   - حماية كاملة للأرقام القومية المصرية (14 رقماً) وأرقام الهواتف والعناوين عبر الحجب المشفر (Data Masking) في الجداول العامة والتقارير المجمعة.
   - مصادقة ثنائية حقيقية (MFA / TOTP) مشفرة بواسطة AES-256، وحماية متقدمة ضد هجمات CSRF، وتجزئة كلمات المرور عبر خوارزمية Scrypt الحديثة.
   - سجل رقابة وتدقيق شامل (`audit_logs`) يوثق كافة العمليات الحساسة في النظام.

## 🛠️ متطلبات التشغيل والتثبيت (Getting Started)

### المتطلبات الأساسية
- **Node.js**: الإصدار 18 أو أحدث.
- **قاعدة بيانات PostgreSQL**: قاعدة بيانات سحابية (مثل Neon) أو محلية.

### خطوات التثبيت والتشغيل المحلي

1. **نسخ مستودع المشروع**:
   ```bash
   git clone https://github.com/manar765/SANAD.git
   cd SANAD
   ```

2. **تثبيت الاعتماديات**:
   ```bash
   npm install
   ```

3. **إعداد متغيرات البيئة**:
   قم بنسخ ملف الإعدادات النموذجي `.env.example` إلى `.env`:
   ```bash
   cp .env.example .env
   ```
   ثم قم بضبط متغير `DATABASE_URL` برابط الاتصال الخاص بقاعدة بيانات PostgreSQL.

4. **تشغيل النظام**:
   ```bash
   # تشغيل خادم الإنتاج / القياسي
   npm start

   # أو تشغيل بيئة التطوير والمراقبة الحية
   npm run dev
   ```
   عند بدء التشغيل، سيقوم النظام تلقائياً بتطبيق جميع ترقيات قاعدة البيانات (`schema migrations`) بفضل القفل المعاملاتي الآمن وإنشاء الحساب الإداري الافتراضي.

5. **فتح المنصة في المتصفح**:
   تفضل بزيارة: [http://localhost:3000](http://localhost:3000)

## 📚 دليل واجهات برمجة التطبيقات (API Reference Catalog)

### المصادقة وإدارة الحسابات
- `POST /api/auth/login`: تسجيل الدخول وتوليد الجلسة والكوكيز الآمنة.
- `POST /api/auth/signup`: تسجيل حساب جديد (متبرع أو مستفيد).
- `POST /api/auth/logout`: تسجيل الخروج وإلغاء الجلسة.
- `GET /api/auth/csrf`: الحصول على رمز الحماية من هجمات تزوير الطلبات (CSRF Token).
- `GET /api/auth/sessions`: استعراض جلسات المستخدم النشطة.
- `POST /api/auth/mfa/setup`: تهيئة وتفعيل المصادقة الثنائية TOTP.

### التبرعات والمستودعات
- `GET /api/donations`: استعراض التبرعات العينية المتاحة.
- `POST /api/donations`: تقديم طلب تبرع عيني جديد.
- `GET /api/inventory`: استعراض عناصر المخزون بالمستودعات مع الفلاتر.
- `POST /api/inventory`: إضافة صنف مخزني جديد (خاص بالمشرفين).
- `PATCH /api/inventory/:id`: تحديث بيانات أو حالة صنف مخزني.

### المستفيدين والاحتياجات
- `GET /api/beneficiaries`: قائمة المستفيدين مع حجب البيانات الحساسة (للمشرفين).
- `GET /api/beneficiaries/:id`: تفاصيل المستفيد الكاملة، الاحتياجات، وسجل الدعم والتوزيعات.
- `POST /api/beneficiaries`: إضافة ملف مستفيد جديد.
- `PATCH /api/beneficiaries/:id/verification`: اعتماد أو تعديل حالة التحقق لملف المستفيد.
- `GET /api/beneficiaries/:id/recommendation`: تشغيل محرك القواعد واستخراج التوصية الاسترشادية.

### التوزيعات الميدانية
- `GET /api/distributions`: قائمة عمليات التوزيع المنفذة والمجدولة.
- `POST /api/distributions`: إنشاء وتأكيد أمر توزيع جديد مع الخصم الذري من المخزون وتحديث الاحتياجات.
- `PATCH /api/distributions/:id/cancel`: إلغاء أمر توزيع مع استرداد الكميات للمخزون تلقائياً.
- `GET /api/distributions/stats`: إحصائيات التوزيعات ونسب التسليم.

### الذكاء الاصطناعي ولوحة التحكم
- `POST /api/ai/analyze`: استخراج البيانات المنظمة من تقارير الحالات الاجتماعية غير المهيكلة.
- `GET /api/dashboard/summary`: المؤشرات التشغيلية الحية، والتنبيهات، وحالة المخزون.
- `GET /api/reports/analytics`: تقارير وإحصائيات مجمعة حسب الفئات والمحافظات خالية تماماً من البيانات الشخصية.
- `GET /api/notifications`: التنبيهات التشغيلية الحية لشريط الرأس (نقص المخزون، أوامر قيد الانتظار).
- `GET /api/admin/audit-logs`: استعراض سجل الرقابة والتدقيق الأمني مع الفلاتر.

## 🔒 إرشادات نشر الإنتاج (Production Deployment)

- **استخدام HTTPS**: تأكد من تشغيل المنصة خلف خادم وسيط عكسي (Reverse Proxy مثل Nginx أو Caddy) لتوفير شهادات SSL/TLS تلقائية.
- **تأمين الجلسات**: عند تعيين `NODE_ENV=production`، تصبح كوكيز الجلسات محمية بالسمات `HttpOnly`, `SameSite=Lax`, `Secure`.
- **حماية الواجهات البرمجية**: الخادم مزود بآليات تقييد معدل الطلبات (Rate Limiting) لمنع الهجمات العشوائية على واجهات الدخول.
- **النسخ الاحتياطي**: يُنصح بجدولة نسخ احتياطي دوري لقاعدة بيانات PostgreSQL للحفاظ على سجلات الرقابة وتاريخ التوزيعات.
